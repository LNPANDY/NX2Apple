**v1.5.0: Hot framework loading for iOS and engine sync / iOS 热加载游戏框架与引擎同步**

## English

**Highlights**

- Hot-load signed game frameworks from `Documents/Frameworks` in the iPhone and iPad shell (#1217)
- Externalize oversized `msl` shader libraries, repack shared IPAs, and batch-transfer built games (#1216)
- Slim down the fork patch queue from 92 to 44 patches and unify `DmShell` under `frontend-ios/Shell` (#1214, #1215)
- Sync upstream engine to `0c078130` (shader chain `a5e7fb6e4fa4`) and fix aliased virtual pool flags and sampler pool bounds for Super Mario Party (#1226, #1227)

**New**
- **Hot-loaded iOS game frameworks**: `ShellHost` and the launcher support dropping signed `DmGame` frameworks into `Documents/Frameworks` so new or rebuilt games load without rebuilding the shell IPA (#1217)
- **Externalized MSL shaders, shared IPA repacking, and batch transfers**: oversized `msl` shader archives are kept external to stay under sideloading size budgets, shared IPAs repack in place, and built games transfer in batches (#1216)

**Changed**
- **Upstream engine**: pinned at `0c078130` with shader chain `a5e7fb6e4fa4` (#1226)
- **Patch queue and project layout**: synthesized `docs/env_switches.tsv`, dropped 14 obsolete patches, squashed fix-on-fix patches, and moved `DmShell` into `frontend-ios/Shell`, bringing the patch stack down to 44 patches (#1214, #1215)

**Fixed**
- **NVN aliased virtual pools and sampler bounds (Super Mario Party)**: aliased virtual memory pools (`vmode == 1`) inherit physical backing pool flags for texture uploads while keeping `CPU_NO_ACCESS` checks in map calls, pre-mapped pool uses keep sparse mode (`vmode == 2`), `nvnSamplerPoolInitialize` bounds sentinel sampler IDs such as `4095` as empty slots without `[RED]` errors, and `dm_gfx_teardown` resets sampler pool state between iOS game sessions (#1227, seedds/nxnative#2519, seedds/nxnative#2513)

**Requires**
- iOS or iPadOS 26 or later
- To build NVN games on a Mac: Xcode 27.2 and macOS 26.6 or later

## 中文

**重点**

- iPhone 与 iPad 壳应用支持从 `Documents/Frameworks` 热加载已签名游戏框架（#1217）
- 支持超大 `msl` 着色器外置、共享 IPA 重打包与批量传输游戏数据（#1216）
- 分支引擎补丁队列由 92 个精简至 44 个，并将 `DmShell` 收拢到 `frontend-ios/Shell`（#1214、#1215）
- 同步上游引擎至 `0c078130`（着色器链 `a5e7fb6e4fa4`），并修复《Super Mario Party》别名虚拟内存池标志与采样器越界崩溃问题（#1226、#1227）

**新增**
- **iOS 游戏框架热加载**：`ShellHost` 与启动器支持从 `Documents/Frameworks` 动态加载已签名游戏框架，无需每次重新打包安装整个壳 IPA（#1217）
- **超大着色器外置、共享 IPA 重打包与批量传输**：超大 `msl` 着色器库可独立外置以满足侧载包体限制，并支持共享 IPA 直接重打包与多游戏批量传输（#1216）

**变更**
- **上游引擎**：固定点更新至 `0c078130`，对应着色器链版本 `a5e7fb6e4fa4`（#1226）
- **补丁队列与工程结构**：改为自动合成 `docs/env_switches.tsv`、清理 14 个过时补丁、合并修复补丁并将 `DmShell` 迁入 `frontend-ios/Shell`，最终保留 44 个分支补丁（#1214、#1215）

**修复**
- **NVN 别名虚拟内存池与采样器越界保护（Super Mario Party）**：`vmode == 1` 别名虚拟内存池在贴图上传与脏区追踪时继承底层物理存储池标志，同时保留 `CPU_NO_ACCESS` 映射拦截，映射前已使用的虚拟池保留稀疏模式（`vmode == 2`），`nvnSamplerPoolInitialize` 记录容量并将 `4095` 等越界哨兵采样器 ID 视为空槽，不再输出 `[RED]` 报错，同时 `dm_gfx_teardown` 在 iOS 游戏切换间重置采样器池状态（#1227、seedds/nxnative#2519、seedds/nxnative#2513）

**系统要求**
- iOS 或 iPadOS 26 及以上版本
- 在 Mac 上构建 NVN 游戏：Xcode 27.2 与 macOS 26.6 及以上版本
