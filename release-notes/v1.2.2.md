**v1.2.2: Fix for the iPhone and iPad shared app shader library copy, and end-to-end nxbuild in the experimental builder.**

## English

**New**
- **Experimental builder runs `nxb build` end to end**: when Settings, Use experimental builder is turned on, the Mac launcher now runs `nxb build` for the whole game build and does not run the Python build script at all, for a Mac app and for the iPhone and iPad options. It reads NSP, NSZ, XCI, merged packages, a Switch 2 NUP, a game folder and DLC, and surveys a game with no profile. There is no fallback to the script: a case `nxb` does not take, or a failure, shows `nxb`'s exit code and its last error line. The app bundles `nxbuild 0.5.1`. The setting is off by default and nothing changes for a default build (#749, #794)

**Fixed**
- **iPhone and iPad shared app build (`FAIL: copy the shader libraries`)**: since the 1.2.0 engine pin `7249ee9f95ed`, an NVN game's iOS shader library is packed into the single file `shader/ios/b-<chain>.img` and the folder `b-<chain>/` is removed. The framework build step for the shared iPhone and iPad app still looked for the folder, so every NVN game build for the shared shell stopped at `rsync: .../shader/ios/b-223f10d34f97/: (l)stat: No such file or directory` and `FAIL: copy the shader libraries`. It now copies `b-<chain>.img` into the game framework's `msl/` folder, where the host loads it. Reported by @zhukangyu26-stack, @tnt739660506-prog and @caixukun1919810114514. By @xiaofeng-han (#781, #795, #800, #782)
- **Windows game folder build (`FileNotFoundError: [WinError 2]` at `pack v...`)**: `pack_dump.py` tried `cp -c` for an APFS clone before falling back to `shutil.copy2`, which raised `FileNotFoundError` on Windows where `cp` does not exist. The Windows driver and shim now copy directly without spawning `cp` or `xattr`
- **Windows shader split on 32+ thread CPUs (`ValueError: max_workers must be <= 61`)**: the Windows build environment and `ProcessPoolExecutor` now cap worker count at 61, CPython's `WaitForMultipleObjects` limit on Windows
- **Windows iOS shader build in Chinese or non-ASCII folders (`no iOS shader libraries`)**: Apple's Windows `metal.exe` and `metallib.exe` fail to open paths containing non-ASCII characters or spaces. The Windows `xcrun` shim and shader cache/PCH helpers now stage non-ASCII inputs and outputs through a pure-ASCII temporary folder
- **Windows first-run setup assistant**: opening the Windows launcher for the first time now presents the guided setup dialog automatically once dependency detection finishes

**Known issues**
- **Experimental builder (`nxb build`)**: the iPhone and iPad path and the new input kinds have not yet been run on a device with real game files (#749, #794)

**Requires**
- iOS or iPadOS 26 or later
- To build NVN games on a Mac: Xcode 27.2 and macOS 26.6 or later

## 中文

**新增**
- **实验性构建器全程运行 `nxb build`**：开启设置里的「使用实验性构建器」后，Mac 启动器现在直接运行 `nxb build` 完成整个游戏构建，完全不运行 Python 构建脚本，Mac App 和 iPhone、iPad 选项都是如此。它读取 NSP、NSZ、XCI、合并包、Switch 2 NUP、游戏文件夹和 DLC，并勘测没有配置的游戏。不会退回脚本：`nxb` 不支持的情况或失败时，会显示 `nxb` 的退出代码和最后一条错误。App 内置 `nxbuild 0.5.1`。该设置默认关闭，默认构建不受影响（#749、#794）

**修复**
- **iPhone 和 iPad 共用壳 App 构建（`FAIL: copy the shader libraries`）**：从 1.2.0 的引擎版本 `7249ee9f95ed` 起，NVN 游戏的 iOS 着色器库会被打包成单个文件 `shader/ios/b-<chain>.img` 并删除原文件夹 `b-<chain>/`。共用 iPhone 和 iPad 壳 App 的框架构建步骤仍在查找原文件夹，导致所有 NVN 游戏的共用壳构建都在最后停在 `rsync: .../shader/ios/b-223f10d34f97/: (l)stat: No such file or directory` 和 `FAIL: copy the shader libraries`。现在它会把 `b-<chain>.img` 复制进游戏框架的 `msl/` 目录供宿主直接读取。由 @zhukangyu26-stack、@tnt739660506-prog 和 @caixukun1919810114514 报告。作者 @xiaofeng-han（#781、#795、#800、#782）
- **Windows 游戏文件夹构建（`pack v...` 阶段报 `FileNotFoundError: [WinError 2]`）**：`pack_dump.py` 在回退到 `shutil.copy2` 前会先尝试运行 `cp -c` 做 APFS 克隆，而在没有 `cp` 命令的 Windows 上直接抛出了 `FileNotFoundError`。现在 Windows 驱动和垫片层直接复制文件，不再调用 `cp` 或 `xattr`
- **Windows 32 线程及以上 CPU 在 `shader split` 阶段报 `ValueError: max_workers must be <= 61`**：Windows 构建环境与 `ProcessPoolExecutor` 现在将工作进程数上限封顶在 61（Windows 版 Python `WaitForMultipleObjects` 的硬上限）
- **Windows 中文或非 ASCII 目录构建 iOS 着色器失败（`no iOS shader libraries`）**：苹果 Windows 版 `metal.exe` 与 `metallib.exe` 无法打开含中文或空格的路径。现在 Windows `xcrun` 垫片及着色器预编译头/编译缓存会自动通过纯 ASCII 临时目录暂存并回写输入输出文件
- **Windows 首次启动设置向导**：全新首次打开 Windows 启动器时，依赖检测完成后会自动弹出引导式设置向导

**已知问题**
- **实验性构建器（`nxb build`）**：iPhone 和 iPad 路径以及真实游戏文件的新输入类型尚未在真机上运行过（#749、#794）

**系统要求**
- iOS 或 iPadOS 26 或更高版本
- 在 Mac 上构建 NVN 游戏：Xcode 27.2 和 macOS 26.6 或更高版本
