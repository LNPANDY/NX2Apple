**v1.2.1: Games with no profile can be built from a NUP or a game folder, older-device iPhone fix, build progress that stays across windows, and fixes for tests and CI.**

## English

**Fixed**
- **Games with no profile: NUP and game folder**: the Mac launcher no longer refuses a Switch 2 NUP or a game folder of a game the engine has no profile for, and the build button is there. When the engine can survey the game itself, the build starts from a provisional profile. An older engine keeps the old message. This only lets the build start. Such a game does not run yet. The first case is Ocarina of Time on Switch 2, and it needs engine work upstream (seedds/nxnative#1299). Reported by @xdgpx and @kianrafiee (#748, #721, #783)
- **Compatibility switch for older iPhones and iPads (A15, A16)**: the switch wrote a key the game never read, and the iOS build removed its environment file. Now it writes `DM_PROF_TEX_BC_CPU=1`, the game's framework keeps `dm/env.txt`, and the shell loads it after the player's own env files, so a file in Documents still wins. The check for a device without native BC textures reads the same setting. Reported by @Sword-Wen. By @thehobbit85 (#719, #723)
- **Build progress and log across launcher windows**: another or a reopened launcher window showed an idle Builds page while a build kept running. All windows now share the running build, its progress, its log and the Stop button. By @thehobbit85 (#405, #724). Reported by @sshuai001
- **Low disk space while building the Metal archive**: when the engine stops because the build volume is full, both launchers now show a failure row. It names the free space the engine asks for, and tells you to free space or pick a build folder on another drive. The text is in all six languages. Reported in #463. By @thehobbit85 (#725)
- **`DM_PSO_BUNDLE=off` on iPhone and iPad**: the shell ignored it in `Documents/env.txt` when a game or framework had a `pso/` folder. Now the launch settings, the game's env file and the shared env file win over the archive the shell finds by itself. The README says how to turn the archive off for one game. This does not fix the Metal crash on iPhone Air (A19 Pro, iOS 27.0) reported in #640. It only makes the switch usable. By @thehobbit85 (#726). Reported by @sheepyd (#640)
- **Tests and CI**: the Tool tests job no longer stays green when an engine test file fails, and the tests it then showed are repaired (#690, #722). A shell test accepts the label `16:9 (Switch)` in German, Swedish, French and Italian (#727). The Mac and shell language-row tests now run the synced engine and check its own row, so a new pin cannot change it unseen. The test steps keep a failure when their output goes through `tee` (#698, #728). All three by @thehobbit85

**Known issues**
- **Games with no profile do not run yet**: the launcher builds them, but a game such as Ocarina of Time on Switch 2 does not run yet. It needs upstream work (seedds/nxnative#1299). The build was not run with a real game or the real engine (#748, #721, #783)
- **Preparing the shared app with a provisional profile**: reported in #757, the UI step that prepares the shared iPhone app can stop with "no game profile" for a game whose profile came from the survey. This release does not change that (#757)
- **Older iPhones and iPads**: the switch was tested with synthetic checks only. Nobody tried it on an A15 or A16 device with a real game (#723)
- **Low disk space row**: checked with the engine's real messages and a synthetic failure. Nobody filled a disk to see it. The Qt launcher was not run (#725)
- **Build progress across windows**: tested with a synthetic build. Nobody closed and reopened a window during a real game build (#724)
- **Metal archive crash on iPhone Air**: the switch to turn the archive off works, and the crash itself is not understood (#640)

**Requires**
- iOS or iPadOS 26 or later
- To build NVN games on a Mac: Xcode 27.2 and macOS 26.6 or later

## 中文

**修复**
- **没有配置的游戏：NUP 和游戏文件夹**：Mac 启动器不再拒绝引擎没有配置的 Switch 2 NUP 或游戏文件夹，构建按钮会显示。引擎能自己勘测游戏时，构建从临时配置开始。旧版引擎仍显示原来的提示。这只是让构建可以开始，这样的游戏现在还不能运行。第一个例子是 Switch 2 上的 Ocarina of Time，它需要上游的引擎工作（seedds/nxnative#1299）。由 @xdgpx 和 @kianrafiee 报告（#748、#721、#783）
- **老 iPhone 和 iPad（A15、A16）的兼容开关**：开关写入的键游戏从不读取，iOS 构建还会删除它的环境文件。现在它写入 `DM_PROF_TEX_BC_CPU=1`，游戏的框架保留 `dm/env.txt`，壳 App 在玩家自己的 env 文件之后加载它，所以 Documents 里的文件仍然优先。对不支持原生 BC 纹理的设备的检查读取同一个设置。由 @Sword-Wen 报告。作者 @thehobbit85（#719、#723）
- **多个启动器窗口之间的构建进度和日志**：另开或重开的启动器窗口会显示空闲的构建页，而构建仍在运行。现在所有窗口共用正在运行的构建、进度、日志和停止按钮。作者 @thehobbit85（#405、#724）。由 @sshuai001 报告
- **构建 Metal 归档时磁盘空间不足**：引擎因构建磁盘已满而停止时，两个启动器现在都显示失败提示，写明引擎要求的空闲空间，并建议腾出空间或选另一块磁盘上的构建文件夹。文字有六种语言。在 #463 里报告。作者 @thehobbit85（#725）
- **iPhone 和 iPad 上的 `DM_PSO_BUNDLE=off`**：游戏或框架有 `pso/` 文件夹时，壳 App 会忽略 `Documents/env.txt` 里的它。现在启动设置、游戏自己的 env 文件和共用 env 文件优先于壳 App 自己找到的归档。README 说明了如何为单个游戏关闭归档。这并没有修复 #640 报告的 iPhone Air（A19 Pro，iOS 27.0）上的 Metal 崩溃，只是让这个开关可用。作者 @thehobbit85（#726）。由 @sheepyd 报告（#640）
- **测试和 CI**：Tool tests 任务在引擎测试文件失败时不再显示成功，并修复了因此暴露的测试（#690、#722）。壳 App 的一个测试接受德语、瑞典语、法语和意大利语里的 `16:9 (Switch)` 标签（#727）。Mac 和壳 App 的语言行测试现在会运行已同步的引擎并检查它自己的行，新的引擎版本不会再悄悄改变它。测试步骤的输出经过 `tee` 时也会保留失败（#698、#728）。三项都由 @thehobbit85 完成

**已知问题**
- **没有配置的游戏还不能运行**：启动器能构建它们，但像 Switch 2 上的 Ocarina of Time 这样的游戏还不能运行，需要上游的工作（seedds/nxnative#1299）。构建没有用真实游戏或真实引擎运行过（#748、#721、#783）
- **用临时配置准备共用 App**：在 #757 里报告，对配置来自勘测的游戏，准备共用 iPhone App 的界面步骤可能以「no game profile」停止。本版本没有改变这一点（#757）
- **老 iPhone 和 iPad**：这个开关只用合成检查测试过，没有人在 A15 或 A16 设备上用真实游戏试过（#723）
- **磁盘空间不足的提示**：用引擎的真实消息和合成故障检查过，没有人真的写满磁盘去看它。Qt 启动器没有运行过（#725）
- **窗口之间的构建进度**：用合成构建测试过，没有人在真实游戏构建期间关闭并重开窗口（#724）
- **iPhone Air 上的 Metal 归档崩溃**：关闭归档的开关可用，崩溃本身的原因还不清楚（#640）

**系统要求**
- iOS 或 iPadOS 26 或更高版本
- 在 Mac 上构建 NVN 游戏：Xcode 27.2 和 macOS 26.6 或更高版本
