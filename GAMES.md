# Games

Every game this fork has a profile for, with the update NSP each one needs. The player's page is [README.md](README.md), and [dm/games/README.md](https://github.com/seedds/nxnative/blob/f25fa9562ee96d06f1e6412dbb91aab2b7035ec1/dm/games/README.md) lists the same games with the engine's own notes on each. This page is the full list, so the README stays short. 中文：[GAMES.zh-CN.md](GAMES.zh-CN.md).

## Switch 2 games

The engine runs Switch 2 games as ordinary profiles. There is no Switch 2 switch or setting. A Switch 2 game is built from a folder of its files or from one NUP container (a `.nup` file), never from NSP or XCI, and needs no `prod.keys`. It builds only when the engine has a profile for it. The launcher takes both forms on the Builds page (pick the folder, the `.nup` file, or a folder that holds the `.nup`) and marks the game **Switch 2** in the library.

The folder layout the engine reads (`updates` and `dlc` are optional):

```
<game folder>/
  base/exefs/                     main, main.npdm, sdk, rtld
  base/romfs/
  updates/458752/exefs/, romfs/   the update's version as a decimal number, the patched RomFS
  dlc/040074a01bf13001/0/romfs/   the DLC's title ID
```

A folder of files has no control data, so the app gets no icon and takes its name from the profile. A NUP may carry both. The first build of a Switch 2 game takes long (Donkey Kong Bananza builds about 23,000 shaders) and needs free space for the RomFS images plus about 6 GB. This page and the launcher do not say how to get the files: they come from your own console.

**The jetsam budget is the limit on big titles, and it can be raised.** Without
`com.apple.developer.kernel.increased-memory-limit` an iPhone gives this app ~3,375 MB (measured on
a 12 GB device: Tears of the Kingdom was killed entering the world map at 3,342 MB resident with
33 MB of headroom. Lowering the render scale to 0.5 did not change it, so the limit is the guest
heap, not the GPU). The app requests the entitlement and `build_ipa.sh` embeds it in a placeholder
ad-hoc signature — an unsigned binary has no signature for a sideloader to read entitlements from,
so without that step the request would be lost. **AltStore Classic 2.2+**, **Impactor** and **Xcode
with a Personal Team** keep it. **SideStore** with a free Apple ID needs a one-time App ID fix,
but **Sideloadly** does not. See [ENTITLEMENTS.md](ENTITLEMENTS.md) for the steps and how
to tell from `Documents/log.txt` (resident + headroom: ~3,375 MB = not in effect, 6–8 GB = it is).
